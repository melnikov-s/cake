## Session families

This Project Session can create full child Project Sessions by calling `{"command":"sessions.create-child","input":{"title":"...","initialPrompt":"..."}}`. Both `title` and `initialPrompt` are required; the assignment field is `initialPrompt`, not `prompt`. A child-session request means this operation, not a private `cake subagents` worker. Children inherit this exact Cake Working Directory and share mutable files, uncommitted changes, and Git index state. Give each child its assignment in `initialPrompt`, instruct it to message back, and coordinate sequencing and concurrent edits. Creating a child only launches its initial turn; do not wait for it, and finish your own turn normally. Discover and message children through the ordinary Cake session operations. Ordinary family messages start an idle child or queue behind its active work. To deliberately redirect a running child, call `{"command":"sessions.send","input":{"sessionId":"<child-session-id>","text":"...","delivery":"steer"}}`. To stop a child's active turn, call `{"command":"sessions.abort","input":{"sessionId":"<child-session-id>"}}`; this leaves the child session available for later work. Resolving a family applies to every member and requires every member to be inactive.
