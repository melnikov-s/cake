# Antigravity turns in Cake

In an open desktop Project Session or an existing permanent Project Chat, choose **Change model → Gemini · via Antigravity**. The installed Google CLI chooses the concrete Gemini model. The choice applies only to that composer; **Return to Pi** restores the unchanged Pi configuration. This route accepts one plain-text turn at a time. It isn't available for drafts, global Cake Chat, the companion, side chats, basic browser chat, workers, schedules, or automations.

## What Cake sends

ACP does not offer a system-prompt override. Antigravity keeps its own system prompt and CLI controls. Cake sends the same portable Cake guidance used on the Pi route, in a separate text block before the exact current user message. There is no Antigravity-specific instruction set. Pi-only workflows and capability instructions stay on the Pi route. This text does not replace Antigravity's provider system instructions. Cake doesn't send the Pi system prompt, settings, tool manifest, attachments, or generated reminders. Selecting Antigravity gives its CLI the conversation's working directory and its normal workspace access; ACP setup is not a filesystem sandbox.

- **Project Session:** Cake sends its instructions and the current message, not Pi history. If the CLI advertises resume and the saved checkpoint still belongs to the current branch, Cake resumes Antigravity's own state without replaying a transcript. Otherwise it starts fresh. Cake never reads Antigravity's local history.
- **Project Chat:** Each turn starts a fresh ACP session, even if resume is advertised. In addition to the instructions and message, Cake may send bounded extracts from your earlier Project Chat messages and Antigravity replies in that chat, explicitly marked as historical data, not instructions or authorization. Cake does not copy the Pi memory summary: it may combine tool output, worker reports, other conversations, or private operational context. The Antigravity view runs the same OptMem selection and consolidation locally on eligible text from this chat's own Durable originals. Pi replies, tool records, imported side-chat history, reports, schedules, attachments, and internal context are excluded. The derived view omits recall handles and is not a second transcript. The configured memory budget and context cap also bound this view. Cake conservatively counts serialized frame bytes against the context limit, including the wrapper. A current message that can't fit is rejected rather than truncated. Don't put secrets in chat text you intend to share; Cake doesn't classify arbitrary values typed or pasted into dialogue.

## Transcript, recall, and permissions

Project Chat retains one Durable history. User content is saved separately from the transport instructions and selected memory. The external reply and brief tool activity are recorded in the same history, with reply text labeled as external context for later Pi turns. Pi's ordinary OptMem summaries, manual compaction, Context inspector, and original-message access remain local to Cake, including across route switches. When using Antigravity, open that history or the Context inspector yourself to retrieve details; Antigravity cannot call Zoom, `archive_search`/`archive_read`, or any other Cake tool. If you want to send specific details, paste the text you intend to share. There is no shell fallback for Cake tools.

The requesting desktop receives the CLI's ACP permission requests. Cake offers only per-call **Allow once** or **Deny**. Cancel, a disconnect at the permission prompt, expiry, and a request that cannot be safely presented never authorize it. Existing Antigravity CLI rules may allow or deny actions without asking. Stop cancels the turn's subprocess without starting Pi or replaying the prompt. A crash can leave the saved user message without a reply; Cake does not retry it automatically.

Cake does not provision MCP, terminal/filesystem client capabilities, authentication, attachment transport, ACP steering or commands, or diff replay. The Pi tool-pruned branch and native side-chat export are not ways to migrate Antigravity context.

## Local smoke test with Google's CLI

Use a disposable empty project. From the environment that launches Cake, check `command -v agy` and `agy acp --help`. If not signed in, run `agy` interactively and use Google's sign-in flow yourself. Cake does not install the executable or perform sign-in. See [Google's ACP setup](https://antigravity.google/docs/ide/extensions/acp/#other-clients) and the [ACP v1 protocol](https://agentclientprotocol.com/protocol/v1/session-setup).

1. In a Project Session, send a Pi message, select Antigravity, and ask it to reply `agy-one` with no tools. Return to Pi and ask what Antigravity said. Confirm the two routes share one transcript.
2. Select Antigravity again in the Project Session. Check whether its status reports that it resumed its own context or started fresh; the intervening Pi turns were not sent.
3. In an existing Project Chat, select Antigravity and send a text turn. Check the disclosure and fresh-session notice. Return to Pi, compact via the Context inspector, and open a memory range. Re-select Antigravity and send again. Confirm the earlier originals remain in the same history.
4. To test permissions, ask Antigravity to run `printf cake-acp` in the empty workspace. Deny it if prompted. Existing CLI rules may handle that command without prompting; don't change global rules solely for this smoke test.
