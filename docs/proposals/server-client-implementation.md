## Current policy: single-user session desktop controller

Cake serves **one user with multiple views**, not multiplayer. Pi remains the sole transcript/queue authority; project/session-scoped updates reach all relevant connected views. A queued input's submitting client is **not** its future device recipient. At dispatch of a new device request, use the session's current designated eligible Electron desktop, or fail explicitly unavailable. Never broadcast actionable native commands or accept first-response-wins. Pending requests retain their actual recipient and correlation after dispatch, including across a controller change. Disconnect clears designation and settles pending requests without aborting accepted server work. Browser-only/headless sessions have no native recipient.

**Designation:** a successful Project Session or Cake Chat open, or explicit desktop start/prompt/steer/follow-up, binds its desktop. Deliberately opening/submitting on another desktop changes the recipient for subsequent requests. Mere `conversations.observe`/catalog inspection does not claim it, and browser observation/submission cannot replace an existing desktop controller. This reuses the ephemeral session binding, not a new Pi queue. Browser UI interactions remain limited; Browser native requests, widget capture, project/Cake Chat controls and Draw require a desktop. Keep native window/session authorization, preview/editor leases and direct requesting-connection provider-auth/files actions; neither session binding nor transcript fanout authorizes broadcasting private auth URL/code/credentials.

**Historical proposal, superseded:** immutable per-turn originating-client affinity would require upstream Pi SDK ownership support for mixed-origin queued inputs. A prior ALS-only experiment was reverted. Neither an SDK patch nor a dependency override is required by this approved single-user policy. Multiplayer ownership/access isolation is deferred. Historical notes below document the old decision process, not current acceptance criteria.

**Independent review:** A real local IPC/remote desktop Cake Chat control-stream regression reproduced a policy defect: passive `cakeChats.observeControls` re-bound the controller to the observing desktop. The stream now filters pending controls by actual recipient without changing the binding. Cake Chat `open` now binds only after a successful open, consistent with Project Session open; failed Project Session open cannot steal the controller. The real IPC/socket test checks passive observation, wrong-recipient response refusal, and failed open while retaining controller. Reviewer rechecks passed six desktop-sharing integrations, 13 coordinator units, typecheck, full lint, format/diff checks, desktop/server builds, and three rebuilt Electron cases (Cake Chat/project observation, remote desktop core/retry). The broader author matrix remains separate evidence. This does not change pending request correlation, original-owner editor/preview leases, or initiating-connection provider-auth notice delivery.

**Finite acceptance and evidence:** `tests/integration/desktop-sharing.test.ts` exercises real local IPC plus browser and remote-desktop sockets against shared RPC/domain/session acquisition: desktop start, browser observation/input, deliberate remote desktop open, pending-reply rejection after switch, subsequent remote dispatch, disconnect settlement/unavailable, surviving accepted server turn, and matching transcript snapshots in local/browser views. Existing network/browser and coordinator tests cover browser-only rejection, correlation and scope; no universal auth fanout or native duplicate execution was introduced. Controlled Pi fixture tests do not prove actual Pi queue scheduling; no per-input provenance is required. Focused checks on settled source: 19 units/3 files and 26 integrations/3 files passed, `pnpm typecheck`, full `pnpm lint`, `pnpm format:check`, both desktop/server builds passed; five targeted rebuilt Electron cases (local Browser, desktop sharing, remote Browser, remote desktop core and retry/local switch) passed.
