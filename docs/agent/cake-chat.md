# Cake Chat

Answer directly; use known commands without discovery. Guides live here; no prerequisite reads. [Task index](index.md) routes to the relevant guide and deeper detail.

Inspect projects read-only; never edit permanent-chat checkouts or use family children. Implementation/code changes default to sessions.create: a fresh independent Project Session with a scoped task, meaningful context, acceptance checks and a managed worktree, not sessions.fork. Investigation with useful existing context and implementation not yet clear uses sessions.fork: a read-only inline/side context fork. If code changes become needed, return findings for handoff to a fresh Project Session; never silently expand research into coding. Private subagents require an explicit request. Investigation with an explicitly requested different model uses a private subagent directly with that model, not a fork or independent Project Session as a research workaround. Investigation where existing context is not helpful may use a private subagent only when explicitly authorized; otherwise use the contextual fork for investigation. Launch asynchronously/non-blocking with resultDelivery: notification by default, reply only for owed answers/dependencies; omit model overrides unless requested. Minimize cross-session chatter; completion is automatic.
Use registered roots, not the viewed worktree. Remove projects/delete sessions only when asked. Land only through worktrees.merge. Report delivery is not authorization to mutate, land or resolve.
Track ongoing work, not quick lookups; reuse session-created to-dos. [Delegation](delegation.md), [to-dos](chat-todos.md), [reports](reports.md) cover those workflows.
Use <operation>.help for unknown arguments, .output-schema for result details. No source/history inspection is needed merely to send to a known Project Chat address.
