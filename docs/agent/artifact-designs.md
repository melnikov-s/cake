# Design evidence and source handoffs

For implementing a reviewed design, not ordinary artifact presentation. [Artifact guide](artifacts.md) supplies publication/revision basics.

## Inspect exact pixels

Publication returns the accepted review PNG as a native image; the user's live rendering is a separate surface and does not prove agent inspection.
Inspect the approved exact `@rN` through `artifacts.preview` or resolved `preview.png`. The brief describes intent, not the approved visual. Read projected source selectively for ambiguous layout/behavior, not private generation history.
Compare the implementation's real screenshot with that same revision and test relevant interactions. One preview covers one bounded initial state, not every theme, viewport or interaction.
For interactive approval, confirm both revision and selected state: initial state A is not evidence for selected option C. Ask for matching live-state pixels when necessary; saved lineage state is advisory and cannot reveal unavailable local state.
Source, descriptions and matching revision numbers alone are not visual proof. If nested tool forwarding gives only text, call the image tool directly or use an image-capable read. Disclose missing pixels rather than claiming inspection.

## Source-only selected option

`artifacts.selection.capture` pins exact revision/digest, stable option ID and observed saved-selection/version evidence. The returned bounded reference contains no code or pixels. Forward that reference, on Workboard for default family coordination.
The receiver links `exactRef`, calls `artifacts.source` to discover selected-option modules and transitive shared dependencies, then reads individual module pages. Do not fetch all alternatives or substitute latest.
Capture requires a validated prototype module manifest; widgets without one fail explicitly. Revision/state drift requires deliberate recapture. Screenshots, other options and generation history are not attached.
Source-only retrieval itself requires no screenshot and is not visual verification. Request visual evidence separately when implementing an approved appearance.

## Scope

Permanent Project Chat/global Cake Chat can link/present accessible artifacts, read saved state, capture selections and inspect selected source, metadata and semantic tools. Generation belongs to Project Sessions.
Recipients must inspect exact approved revisions; copied workspace files and remembered summaries are not a shared artifact baseline. Keep spec revisions and implementation evidence distinct.
